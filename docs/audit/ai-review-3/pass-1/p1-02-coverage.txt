AUTHORITY MODEL CHECKED

- Global singleton bootstrap: InitializeConfig authority is a Signer. Its program_data is the canonical PDA under the upgradeable loader for crate::ID and has upgrade_authority_address == authority.key(). The globals use init, not init_if_needed.
- Governance config changes: ProposeConfig requires the stored governance Signer. ApplyConfig executes only the recorded proposal in its timelock/application window. The report isolates the missing successor acceptance as unsafe-authority-transfer, not a missing current-admin check.
- Emergency actions: cancel_config, set_pause, set_route_broken, and set_venue_extras require the stored emergency/governance Signer. disable_venue and revalidate_venue require the stored emergency Signer. Authority and timelock cancellations stay governance-only. disable_venue removes a pending re-enable for its bit.
- Coverage: set_coverage_pause authenticates the enabled coverage key or emergency clear-only path. The keeper cannot change governance, fee recipients, or general settings through it.
- User positions: lender mutation/payment paths bind the lender PDA to owner Signer; short open/close/add-margin bind borrower Signer. Keeper exits bind the position and exposure to the stored borrower and send residual/rent to that borrower. Keeper rewards are explicitly payable to any keeper Signer.
- sync_lender: the unsigned owner slot is intentional. owner.is_signer selects convert/touch; unsigned calls use touch_pot, then enforce no rebase conversion and no record mutation. No instruction lets an unrelated signer claim that lender's SOL.
- PDA custody: market, trader, trader_wsol, pool_vault, position, and exposure are scoped to market/mint/user as appropriate. A shared market vault is a pool asset, not a private user vault. Withdraw first debits authenticated lender shares and signs only for that market's pool vault.
- Venue signer forwarding: trade CPI constructors explicitly mark only trader as signer. Borrower/keeper and market PDA signatures do not reach venue swap constructors. Extras reject signers, shortwin-owned accounts, and supplied denylist keys and produce nonsigner metas. Fixed token/System/ATA program types or IDs constrain the standard CPIs examined.
- Token custody: listing creates the pool-vault PDA instead of adopting a user token account. Pump base ATA checks owner, mint, delegate, close authority, and frozen state. The mint allowlist rejects freeze authority and every extension except six metadata/group extensions, so permanent delegates, transfer hooks, transfer fees, and mint-close authority are rejected.
- Pre-creation: pool vault and ephemeral WSOL creation handle pre-funded PDAs. Pump base ATA uses create_idempotent. Both UVA helpers skip already initialized venue-owned accounts. No B26 path was confirmed in these helpers.
- Honest admin parameter hazards: kink changes wait until no position is open; existing positions lock rent rates, keeper rewards, penalty splits, exit bounds, and settlement terms. OracleFeed application clears the old cache. No retroactive-rate finding was established in the examined call paths.
