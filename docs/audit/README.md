## RFQ log

**The owner's decision (Q2, 2026-10-02; SPEC §14, ARCH §10):**
- one full private audit of the scope in AUDIT.md §2;
- then a public contest on the fixed code, on Sherlock or Cantina;
- then a bug bounty at the beta (M11).

The owner sends the requests for quotes (RFQs) to OtterSec, Neodyme, Zellic and Offside Labs,
and books both engagements. This package supplies the material. Public queues are 4–12
weeks. The researchers' market figures, ≈ $150–300k for the primary audit and $50–150k for a
contest, are **not verified**.

### What each RFQ carries

1. The one-page summary (AUDIT.md §1) and the scope (AUDIT.md §2 table, `scope.txt`):
   - the on-chain core: 106 Rust files, 21,243 non-test nLOC (30,206 tokei code);
   - the keeper core subset, in scope by the owner's decision: 14 files, 4,692 non-test nLOC
     (7,759 tokei code);
   - out of scope, read for context: the rest of the keeper (5,821) and the governance tool
     with its Squads encoders (4,124). A quote may price them as options.
2. The stack: Anchor 1.2.0, Agave 4.1.2, SBPF v3. The CPI targets: pump.fun, PumpSwap,
   pump-fees, Raydium AMM v4 and CPMM, Token / Token-2022, memo. Governance through Squads v4.
3. The audit commit: the `audit-1` / `v1.0.0` tag (AUDIT.md §0), with the verified hashes.
   The code freeze date and the requested window: set by the owner.
4. Repository access. The repository is private until it goes public (or gets a public
   mirror) before mainnet (owner decision Q3): access by invitation, or a snapshot of the tag.
5. What the quote should state:
   - price;
   - earliest start;
   - duration in engineer-weeks and the number of auditors;
   - method: manual review, fuzzing, formal methods;
   - fix-review terms, including the contest's fix window;
   - whether the report may be published;
   - the price of the context units as options.
