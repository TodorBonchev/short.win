# ShortWin promotional edits

Two 56-second editions of the captured v1.0.3 local-validator demo: landscape
1920×1080 and portrait 1080×1920, both 30 fps. These are edited promotional
excerpts; the original continuous walkthroughs remain in `apps/web/.e2e/demo/`.
No validator, wallet, or product state is changed by this project.

## Open and export

This is an isolated pnpm workspace. Its lockfile and 14-day minimum package age
do not change the application dependencies. Node 24.21+, pnpm 12.7, FFmpeg,
ffprobe and Chromium are used. Remotion is pinned to 4.0.533, the newest release
that met the package-age policy on 2026-10-21. Only esbuild's dependency build
script is enabled.

```bash
cd tools/promo
pnpm install --frozen-lockfile
pnpm prepare:footage
pnpm prepare:audio --offline
pnpm studio
```

Studio opens at `http://localhost:3410`. Select `PromoLandscape` or `PromoPhone`.
The named scenes and video clips are in `src/Promo.tsx`; widths, duration and
frame rate are registered in `src/Root.tsx`. Narration, captions and original
music are generated by `scripts/audio.mjs`. Edit its speech windows together
with the composition if changing the scene durations.

```bash
pnpm typecheck
pnpm render                         # both final MP4s and PNG posters
pnpm render --variant phone         # one edition
pnpm render --preview               # half-size drafts in out/draft
pnpm render --verify-only           # inspect the existing final exports
python3 scripts/bundle.py           # portable editable ZIP, after exporting
```

Final outputs and `export-manifest.json` go to `out/`. The renderer uses two
Chromium workers, PNG intermediate frames, H.264 CRF 18/yuv420p with explicit
limited-range BT.709, stereo AAC at 48 kHz/192 kbps and MP4 faststart. It verifies
dimensions, all 1,680 frames, 56-second video/audio,
full decoding, poster PNGs, SHA-256, −16 ±1 LUFS and true peak at or below
−1 dBTP. Chromium is currently `/usr/bin/chromium` in `scripts/render.mjs`.

## Input assets and offline use

Generated media, fonts and API caches are gitignored. A clean checkout needs
the original captured artifacts or the supplied editable bundle. The bundle
already contains `public/` and cached speech responses: after installing
dependencies, run Studio or render directly. There is no need to prepare
footage again or contact ElevenLabs merely to edit/export that bundle.

`prepare.mjs` reads each existing `render.json` and its silent master. It removes
the old guide strip, verifies dimensions/duration, copies the current brand
assets and Adwaita Sans variable font, and records hashes in
`public/footage/manifest.json`. It preserves the source timeline. Supported
options are `--source-dir`, `--font-file` and `--font-license`; see `--help`.
Default font paths are the Adwaita package installed on this PC. Its included
SIL OFL license is copied alongside the font.

If the speech response cache is missing, `pnpm prepare:audio --offline` stops.
`pnpm prepare:audio --dry-run` prints the script without reading credentials.
To intentionally generate missing speech, run `pnpm prepare:audio`; it uses
ElevenLabs Bella / `eleven_multilingual_v2`, with credentials read only
in-process from `ELEVENLABS_API_KEY` or `~/.11l`. Only narration text and voice
settings are sent to ElevenLabs. It saves successful responses before local
processing and never automatically retries a paid request. API keys are not
stored in the project, cache or bundle. Seven unique requests contain 507 text
characters. All seven clips fit at natural speed.

The score, *ShortWin Quiet Circuit*, is generated locally from sine tones and
an original arrangement at 96 BPM. It uses no external music recordings or
samples. Speech ducks the music before the final two-pass loudness treatment.
`public/audio/manifest.json` records sound hashes, durations and measurements;
`captions.json` and `alignedwords.json` retain the speech alignment.

## Editorial choices

| Promo time | Scene | Treatment |
| --- | --- | --- |
| 0–4s | Rent / sell / buy back | Held populated short preview, animated typography |
| 4–11s | Supply inventory | Create-market review, deposit risk acknowledgment and signing |
| 11–23s | Open a short | Size, collateral, liquidation disclosure, sign and confirmation |
| 23–31s | Buy back and close | Preview, signing, held indexed Closed result |
| 31–39s | Liquidation | Separate scripted mock market; keeper payment recorded |
| 39–49s | S1 settlement | Another mock position; remaining SOL and lender-loss disclosure |
| 49–56s | Call to action | Inspect code, reproduce the demo, follow the build |

Wait intervals and old chapter title cards are omitted. Action excerpts play
at normal speed; explicitly labelled holds extend recorded results. The phone
opening holds source 44.6s; final Closed holds are desktop 69.0s and phone
73.5s, after the indexer has populated the result. Existing captured pointer
and touch highlights are retained. Phone footage is browser emulation, not a
physical-device/wallet-handoff recording. Enlargement cannot add source detail.

The overlays continuously identify an edited local-validator demo and repeat
the test-only mock-market disclosure during both scripted exits. The CTA is
to inspect/reproduce the code. The edits make no mainnet availability, audit,
guaranteed-return or profit claim. They reuse the historical capture; they
are not a new validation run against later audit fixes.
